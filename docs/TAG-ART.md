# 태그 그림 그리기 규칙

말씀 전체화면 배경에 태그 그림을 띄우는 기능(`이미지 삽입`)을 위한 문서다.

**이 문서가 있는 이유.** 태그는 HB가 자유롭게 만들기 때문에 계속 늘어난다.
새 태그가 생길 때마다 "이 그림이 맞습니까?" 하고 물어볼 수는 없다.
그래서 **무엇을 그릴지 고르는 기준**과 **다 그린 뒤 스스로 검사하는 방법**을
여기에 못박아 둔다. 새 태그 그림을 그리는 도구는 이 문서만 보고 혼자 판단한다.

---

## 규칙 1 — 기본은 추상이다 (2026-08-25 결정)

**사물을 그리려 하지 말고 선의 방향으로 뜻을 낸다.** 이게 기본값이다.

1·2차 시안에서 사물(비둘기·손·양·사람)을 계속 시도했지만 전부 실패했다.
단순하게 그리면 귀여워지고, 자세히 그리면 다른 사물로 읽혔다.
정면 비둘기는 여섯 번 고쳐도 군용 휘장에서 벗어나지 못했다.
추상으로 바꾸자 한 번에 풀렸다 — **알아볼 사물이 없으면 잘못 알아볼 일도 없다.**

### 방향 어휘표

| 선의 방향 | 뜻 | 태그 |
|---|---|---|
| ↑ 솟음 | 임함 · 능력 | 성령 · 부흥 · 능력 |
| ↓ 내림 (끊어진 수직선) | 거저 주어짐 | 은혜 · 사랑 · 평강 |
| ⌒ 굽음 (곧은 선이 굽어 바닥에 닿음) | 낮아짐 · 복종 | 순종 · 겸손 · 회개 |
| — 고요 (잔잔한 수평선) | 머무름 · 쉼 | 평안 · 안식 |
| ↗ 퍼짐 (아래에서 위로 벌어짐) | 번져 나감 | 소망 · 전도 |

새 태그를 만나면 **그 단어가 어느 방향인지만 정하면 된다.** 표에 없는 방향이
필요하면 한 줄 추가하고, 왜 그 방향인지 한 문장을 같이 적는다.

밀도(선 개수·간격)로 세기를 조절한다. 성글면 조용하고, 촘촘하면 강하다.

### 한 태그에 그림이 여럿일 수 있다 (2026-08-25 결정)

성경이 한 가지를 여러 상징으로 말하는 경우가 있다. 성령이 그렇다 —
바람(요 3:8)·불(행 2:3)·물(요 7:38)이 전부 성령이다. 이럴 때는 **후보를 다 만들어
두고 말씀 본문에 맞는 것을 고른다.**

고르는 순서:
1. 본문에 그 후보의 **낱말이 있으면** 그것 (예: 본문에 '불'이 있으면 불꽃)
2. 맞는 게 없으면 후보 중 **랜덤**

| 태그 | 후보 | 본문에서 찾을 낱말 |
|---|---|---|
| 성령 | 바람 | 바람 · 숨 · 호흡 · 영 |
| | 불꽃 | 불 · 뜨겁 · 사르 · 태우 |
| | 물 | 물 · 생수 · 샘 · 강 · 부어 |

**새 후보를 넣을 때는 이미 있는 그림과 나란히 놓고 본다.** 뜻이 다른데 모양이
닮으면 둘 다 죽는다. 성령의 '물'을 분수 모양으로 그렸다가 소망(아래에서 위로
퍼짐)과 구별이 안 돼서 버리고, 옆으로 흐르는 물결로 바꿨다.

### 사물로 그려도 되는 예외

**성경에 직접 나오는 표준 상징**이 있고, 그 형태가 단순해서 확실히 읽히는 경우만.
십자가·등불·잔처럼 **기하학적으로 단순한 것**은 된다.
**동물과 사람은 하지 않는다** — 전부 실패했다.

**어느 쪽이든 한 그림에 상징은 하나만.** 비둘기 + 빛줄기 + 구름을 함께 그리면
셋 다 흐려지고 아무것도 안 읽힌다. 1차 시안이 정확히 이래서 실패했다.

**고른 이유를 한 문장으로 못 쓰면 버린다.**
"내리는 비 — 내가 만든 게 아니라 위에서 주어진 것"처럼 근거를 댈 수 있어야 한다.

## 규칙 2 — 그리고 나면 반드시 눈으로 본다 (제일 중요)

코드로만 쓰고 넘기지 말 것. 그린 사람은 자기가 뭘 그렸는지 알기 때문에
무조건 알아보인다. 처음 보는 사람 눈에는 전혀 다른 게 보인다.

```
node tools/icon-shot.js 작업.html 결과.png     # PNG 로 뽑아서 직접 본다
```
(playwright 를 못 찾으면 앞에 `NODE_PATH=$(npm root -g)` 를 붙인다)

**보는 방법**: 태그 이름을 가리고 **"이게 뭐로 보이나"를 먼저 판정**한다.
그 답이 태그와 다르면 그림이 틀린 것이다. 도안을 고치지 말고 **상징을 바꾼다.**

2026-08-25 에 이 검사로 걸러낸 것들 — 전부 코드만 봤을 때는 멀쩡해 보였다:

| 그리려던 것 | 실제로 보인 것 |
|---|---|
| 은혜 = 오목하게 모은 두 손 | 이빨 드러낸 **웃는 입** (손가락 선이 이빨이 됐다) |
| 순종 = 길 위의 발자국 | **밀 이삭** |
| 순종 = 양 | 구름 옆에 붙은 **소용돌이** |
| 은혜 = 구름에서 내리는 빛 | 그냥 **비구름(날씨)** |
| 성령 = 정면에서 본 비둘기 | **비행기·나방** (새는 정면에 실루엣이 없다) |
| 은혜 = 측면으로 편 손 | **초승달·뿔**, 엄지는 소용돌이 |
| 은혜 = 받쳐 든 두 손 | 또 **구름** |
| 순종 = 삼각형 옷자락 | **텐트·산** |
| 은혜 = 잔 + 바깥으로 휘는 넘침 곡선 | 손잡이가 달린 **트로피** |
| 성령 = 정면 비둘기, 날개를 판자로 | **비행기·나방** |
| 성령 = 정면 비둘기, 날개 끝을 톱니로 | **가시·엉겅퀴** |
| 성령 = 정면 비둘기, 깃털을 낱장으로 | **군용 휘장(윙 마크)** |
| 성령 = 정면 비둘기의 부채꼴 꼬리 | 어떻게 그려도 **왕관** |
| 순종 = 옷 입혀 무릎 꿇은 사람 | **앉아 있는 스님** |
| 성령 = 위로 솟는 좌우대칭 잎 모양 | **나뭇잎** (불꽃은 끝이 한쪽으로 기울어야 한다) |

## 규칙 3 — 세 가지 조건에서 확인한다

한 번 크게 봐서 괜찮은 건 아무 의미 없다. 실제로 쓰이는 조건에서 봐야 한다.

1. **크게** (220px) — 형태가 맞는지
2. **작게** (86~100px) — 실제 표시 크기. 가는 선과 잔 디테일이 뭉개져 사라진다
3. **어두운 배경 · 오패시티 20%** — 실제 사용 조건. 여기서 안 보이면 못 쓴다

## 규칙 4 — 그리는 요령 (실패에서 뽑은 것)

- **윤곽선은 사물의 실루엣을 따라간다.** 장식선을 긋지 않는다.
  선 하나하나가 "이 물건의 어느 모서리인지" 답할 수 있어야 한다.
- **짧은 평행선을 여러 개 나란히 긋지 말 것.** 이빨·빗살·이삭으로 보인다.
- **좌우 대칭 + 아래로 볼록**은 웃는 입이 된다. 비대칭으로 깨뜨린다.
- **눈 점 하나**가 생물이냐 아니냐를 가른다. 동물에는 반드시 찍는다.
- 부리·귀처럼 **작고 뾰족한 부분은 본체 윤곽에 넣지 말고 따로 그린다.**
  윤곽에 넣으면 부리가 몸통만큼 두꺼워져서 새가 아니라 원뿔이 된다.
- 사람은 **머리(원) + 몸통 곡선 + 팔다리**로 나눠 그린다. 자세가 곧 뜻이므로
  자세가 읽히는 게 형태보다 중요하다.
- **새·짐승은 반드시 옆모습.** 정면에서 그리면 알아볼 실루엣이 없어 비행기·나방이 된다.
  움직임(내려온다·달린다)은 **몸 전체를 기울여서** 낸다. 화살표나 빛줄기를 덧붙이지 않는다.
- **손은 그리지 않는 편이 낫다.** 정면 손바닥은 'STOP' 과 타 종교의 손 문양으로 먼저 읽히고,
  측면으로 돌리면 초승달·뿔이 된다. 손으로 표현하고 싶은 뜻은 **그릇·잔** 쪽으로 바꾼다.
- 그릇 옆에 **바깥으로 휘는 곡선**을 붙이면 손잡이가 되어 트로피로 보인다.
  넘침·채워짐은 **위에서 떨어지는 방울**로 낸다.
- 사람의 옷자락을 곧은 삼각형으로 그리면 텐트·산이 된다. **목과 어깨선을 반드시 드러낸다.**

## 규칙 5 — 진지한 그림체 (귀여워지지 않기)

단순하게만 그리면 자동으로 귀여워진다. 세 가지가 원인이다.

| 원인 | 기준 |
|---|---|
| 선이 굵다 | viewBox 200 기준 **2.4**. 4 는 만화가 된다 |
| 머리가 크다 | 사람 머리는 전체 높이의 **1/5 이하**. 1/3 이면 데포르메(귀여움)다 |
| 내부가 비었다 | 깃털·옷주름 같은 **내부선 2~3개**(굵기 1.3~1.9)가 밀도를 만든다 |

## 스타일 규격 — 두 벌을 같은 도안으로 만든다

도안(path)은 **하나만** 그린다. 스타일은 그 도안을 어떻게 그리느냐의 차이다.
그래야 나중에 도안을 고치면 두 스타일이 같이 고쳐진다.

**minimal** — 깔끔하고 상징적인 드로잉라인
```
fill="none" stroke-width="2.4" stroke-linecap="round" stroke-linejoin="round"
```
내부 디테일선은 `stroke-width="1.3"~"1.9"` 로 따로 준다.

**organic** — 아날로그·빈티지 펜슬 드로잉
같은 도안에 필터 두 개를 겹쳐 쓴다.
```html
<filter id="wb">  <!-- 손떨림: 저주파로 선을 굽힌다 -->
  <feTurbulence type="fractalNoise" baseFrequency="0.035" numOctaves="2" seed="3" result="n"/>
  <feDisplacementMap in="SourceGraphic" in2="n" scale="3"/>
</filter>
<filter id="gr">  <!-- 연필 결: 고주파로 선을 거칠게 -->
  <feTurbulence type="fractalNoise" baseFrequency="0.8" numOctaves="2" seed="5" result="n"/>
  <feDisplacementMap in="SourceGraphic" in2="n" scale="1.6"/>
</filter>
```
```html
<g filter="url(#wb)"><g filter="url(#gr)" fill="none" stroke-width="2.2"
   stroke-linecap="round" stroke-linejoin="round"><use href="#도안"/></g></g>
```
`baseFrequency` 를 낮추면 흐물흐물해지고, 올리면 지저분해진다. 위 값이 기준선이다.
**선을 얇게 할수록 흔들림(scale)도 같이 줄여야 한다.** 안 그러면 선이 끊어져 보인다.

## 화면에 얹는 규칙

- viewBox 는 **`0 0 200 200`** 으로 통일. 그림은 대략 `30~170` 안에 담는다
- 크기는 화면 폭의 **20%**, PC 등 넓은 화면에서는 최대 **100px** (원래 40%·280px)
- 오패시티 **20%**, 단 **모바일은 30%** (`@media(hover:none)`).
  같은 값이라도 폰에서는 더 옅게 느껴진다는 HB 확인에 따른 것이다 (v26-0826-5).
  ⚠️ 공유 이미지(`_shotDraw`)는 이 숫자를 다시 적지 않고 **화면에 적용된 값을 읽는다**.
  숫자를 두 군데 적으면 이런 기기별 규칙이 생길 때 화면과 공유가 어긋난다.
- 자리는 **본문 바로 위·가로 가운데 고정** (v26-0826-3부터. 원래는 네 모서리 랜덤이었는데
  기존 화면 요소와 겹쳐 복잡해 보였다). 세로 자리는 본문 분량을 따라간다 —
  본문이 길수록 본문 상자가 위로 올라오므로 그림도 함께 올라간다.
  - CSS 로는 못 정한다. `_vfPlaceTagArt()` 가 `#vfText` 상자를 재서 인라인 `top` 을 넣는다.
  - ⚠️ **`#vfArt` 는 `#verseFullInner` 안, `#vfText` 바로 앞에 둔다** (v26-0826-5).
    말씀을 넘기는 애니메이션은 `#verseFullInner` 를 통째로 옮기므로, 밖에 두면
    본문만 밀려가고 그림은 제자리에 남는다. 안에 있으면 둘이 한 덩어리로 움직인다.
    (`#vfText` 보다 뒤로 옮기면 글자를 덮으므로 앞이어야 한다.)
    같은 상자 안이라 `top` 과 `#vfText.offsetTop` 의 기준이 같다 — 보정 없이 그대로 쓴다.
  - ⚠️ **잴 때 `getBoundingClientRect()` 를 쓰면 안 된다.** 말씀을 넘기는 동안
    `#verseFullInner` 는 `translateY` 로 화면 밖에 나가 있는데 `_verseFullRender()` 가
    **바로 그 순간에** 돈다. 그때 재면 본문이 화면 밖에 있는 것으로 나와 "자리 없음"이
    되고 그 상태로 굳는다 — 첫 화면만 뜨고 그 다음 말씀부터 안 뜬다 (v26-0826-3 사고).
    `offsetTop` 은 transform 을 타지 않으므로 넘기는 중에도 참값이 나온다.
  - **`_vfLayoutText()` 끝에서 부른다.** 본문 글자 크기·줄바꿈이 정해진 **뒤**라야 잴 수 있고,
    회전·글자크기 변경 등 다시 그리는 모든 길이 그 함수를 지나므로 자리도 함께 따라온다.
  - 위쪽 여백이 모자라면 그림을 줄이고, 26px 밑으로 내려가면 아예 안 보여준다.
    억지로 밀어 넣으면 닫기 버튼·필터 이름과 겹친다.
    가로로 눕힌 화면(높이 430 이하)은 본문이 이미 위쪽에 붙어 있어 자리가 없다 —
    거기서는 안 뜨는 게 정상이다.
  - 크기 규칙은 **CSS(`.vf-art`) 한 곳**뿐이다. 줄일 때만 인라인 폭을 쓰고,
    다음 배치 때 그 인라인 값을 비운 뒤 다시 읽는다 — 안 그러면 한 번 줄어든 그림이 영영 안 커진다.
- 색은 글자색을 따라간다 (`stroke="currentColor"`) — 테마가 바뀌어도 같이 간다
- 말씀에 태그가 여럿이면 그중 **하나를 랜덤**으로 고른다
- **그림이 없는 태그면 아무것도 그리지 않는다.** 비슷한 걸 갖다 붙이지 말 것

## 코드에 넣는 형식

도안은 `<defs>` 안에 `<g id="ic-태그이름">` 로 한 번만 정의하고,
쓸 때는 `<use href="#ic-태그이름"/>` 로 부른다. 스타일 두 벌이 같은 도안을 공유한다.

태그 이름 → 도안 id 는 표 하나로 관리한다. 표에 없는 태그는 그림 없음으로 둔다.

| `docs/tag-art-samples.html` | 1~3차 시안과 실패 기록 (남겨 둔 것) |

### 도안이나 묶음을 고쳤을 때

`index.html` 안의 `_TAGART_*` 는 **손으로 고치지 말 것.** 도안집이나 묶음표를
고친 다음 아래를 돌려 다시 심는다.

```
python3 tools/make-tagart.py > /tmp/tagart.js   # 만들어 보고
python3 tools/tag-groups.py <태그목록파일>       # 커버리지 확인
node tests/test_tagart.js                       # 테스트
```
그리고 `/tmp/tagart.js` 의 내용으로 `index.html` 의 `_TAGART_MARKS` ~
`_TAGART_GROUPSRC` 구간을 통째로 바꾼다.

### 본문 낱말은 길고 뚜렷하게

도안이 여럿인 묶음(성령)에서 본문 낱말로 고를 때, **한국어는 부분일치가 잘
터진다.** `'불'` 하나만 두었더니 요 3:8 "바람이 임의로 **불**매" 가 불꽃으로
뽑혔다. `'물'`(재**물**·만**물**), `'숨'`(**숨**기다), `'영'`(**영**원)도 같은 함정이다.
틀려도 같은 묶음 안의 다른 그림이 나올 뿐 사고는 아니지만, 뜻이 어긋난다.
`tests/test_tagart.js` 시나리오 3에 회귀 테스트가 있다.

휴대폰에서는 **`https://block7.my/docs/tag-art-marks.html`** 로 열린다.

묶음표를 고쳤으면 커버리지를 다시 잰다:
```
python3 tools/tag-groups.py <태그목록파일>
```

## 설정창 '그림체' 미리보기

minimal / organic 버튼 안의 띠는 **도안이 아니라 획 하나**다 (`_tagartSwatchSvg()`).

⚠️ v26-0826-2 에서 도안을 확대해 잘라 쓴 적이 있는데(`viewBox="50 60 40 40"`),
선을 굵게 키우니 이웃한 획까지 상자를 채워서 **선이 아니라 그 사이 틈**이 보였다.
"위아래가 칠해진 음각" 으로 읽힌다. 도안을 잘라 미리보기로 쓰지 말 것.

- 자체 viewBox `0 0 140 20` 에 획 하나 (`stroke-width="7"`)
- 필터 id 는 도안과 **달라야 한다** (`tagartSwWb`/`tagartSwGr`).
  같은 문서에 도안과 미리보기가 함께 뜨므로 id 가 겹치면 서로 잡아먹는다
- 흔들림·결은 도안보다 세게 준다 (`scale` 2.6 / 2.2). 질감을 확대해 보여주는 자리라서다
