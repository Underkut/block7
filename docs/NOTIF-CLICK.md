# 알림을 눌렀는데 말씀 전체화면이 안 뜨는 문제 — 진단 판 (v. 26-0828-4)

> **알림이 도착하는 문제는 이미 해결됐다.** 여기서 다루는 것은 **누른 뒤**뿐이다.
> 발송·수신·표시 코드는 한 줄도 건드리지 않았다.

---

## 1. 왜 지금까지 못 고쳤나

지금까지는 **끊긴 자리를 모르는 채** 재시도와 우회로만 늘렸다.
진단 기록은 있었지만, 한 알림이 워커에서 앱까지 가는 길을 **하나의 번호로 이어 볼 수 없었고**,
결정적으로 **거짓말을 하고 있었다.**

```js
// 옛 firebase-messaging-sw.js
var saved = withTimeout(savePending(ref, tok), 2000, 'savePending').then(function (r) {
  notes.push('기록 저장 ' + (typeof r === 'string' ? r : '완료'));   // ← r 은 언제나 배열
});
```

`savePending` 은 `Promise.all([...])` 이라 **항상 배열**을 돌려준다.
`typeof r === 'string'` 은 **영원히 거짓**이다. 즉 IndexedDB 저장이 시간초과돼도
진단 기록에는 **"기록 저장 완료"** 라고 찍혔다. 아이폰에서 정확히 그 저장이 멈추는데,
기록만 보면 멀쩡해 보였다.

## 3. 이번에 바꾼 것

### 3-1. 다리를 파이어베이스보다 **먼저** 놓는다  ← 가장 큰 변화

`_initVerseNotifBridge()` 가 스크립트를 읽는 즉시 한 번 불린다.
Firebase·로그인·Firestore 를 **하나도 기다리지 않는다.**
여러 번 불려도 리스너·타이머는 하나만 남는다(idempotent).

- 로그인 화면이 떠 있으면 **열지 않고 기다린다.** 의도는 버리지 않는다 —
  로그인이 끝나면 1.5초 폴링이 곧바로 집어 연다.

### 3-2. 알림 1건 = 고유번호(intentId) 1개

워커가 알림을 띄울 때부터 번호를 붙이고, 클릭·주소·메시지·저장 기록·앱의 모든 단계에
그 번호를 달아 적는다. 진단 기록에서 `#a1b2c3d4` 로 **한 알림의 전 구간이 한 줄기로 보인다.**

담는 칸: `intentId · ref · createdAt · source · swVersion · appVersion · stage · retryCount · expiresAt`

`Date.now()` 만으로 중복을 가르지 않는다(같은 밀리초·시계 되돌림에 무너진다).

### 3-3. 받은 의도를 **화면에 띄우기 전에** 이 기기에 적어 둔다

메시지로만 온 의도는 지금까지 **어디에도 남지 않았다.** 앱이 막 켜지는 중이라
말씀 목록이 없으면 재시도(약 15초)를 다 쓰고 그냥 사라졌다.
이제 `localStorage.b7v1_notifintent` 에 남고, **전체화면이 실제로 확인된 뒤에만** 지운다.

### 3-4. 앱 준비 handshake

앱의 조기 다리가 서면 워커에 `block7-app-ready` 를 보낸다.
워커가 아직 살아 있는 의도를 들고 있으면 그 창에 **다시** 건넨다.
앱이 전체화면을 확인하면 `block7-intent-ack` 를 보내고, 그때 워커가 pending 을 지운다.
(워커 메모리는 언제든 사라지므로 **주 통로는 여전히 IndexedDB 의 pending** 이다)

### 3-5. IndexedDB 연결을 하나만 열고 다시 쓴다

> **왜 "매번 닫기" 가 아니라 "한 번 열고 계속 쓰기" 인가**
> iOS 에서 멈추는 자리는 언제나 **`open`** 이다 — 페이지와 서비스워커가 같은 DB 를
> 붙들고 있으면 한쪽 `open` 이 응답하지 않는다. 매 작업마다 닫았다 여는 방식은
> **open 횟수를 오히려 늘려** 그 위험을 키운다. 그래서 연결 하나를 보관해 다시 쓰고,
> 끊김(`versionchange`·`close`·오류·`abort`)이 보이면 보관을 버려 다음 호출이 새로 연다.
> 1.5초 폴링 기준 **1분에 40번 열던 것이 1번**이 된다.

### 3-6. 시간초과를 절대 성공으로 적지 않는다

`_withOutcome()` / `withOutcome()` 이 `{how:'ok'|'timeout'|'error', ms}` 를 돌려주고,
`_outcomeText()` 가 `성공(12ms)` · `시간초과(1500ms)` · `오류:…` 로 적는다.
저장소 호출마다 **각각** 시간 제한과 결과가 따로 남는다.

### 3-7. 진단 화면 머리줄

`앱 v. 26-0828-4 · 워커 v. 26-0828-4 · controller 있음`
— 앱과 워커는 **따로** 갱신된다. 둘이 다르면 그것이 곧 단서다.
워커가 `(응답 없음 — 옛 워커)` 로 나오면 워커가 아직 옛 버전이라는 뜻이다.

### 3-8. "말씀 클릭 경로 테스트" 버튼

말씀 설정 → 알림 탭 → **말씀 클릭 경로 테스트 → 시작** (관리자 계정에서만 보임).

지금 목록에 **실제로 있는 말씀** 하나를 골라, 진짜 푸시와 **같은 모양의 data**
(`{ref, intentId, type:'verse'}`)로 알림을 띄운다.
그 알림을 직접 누르면 `notificationclick` → 워커 → 앱 → 전체화면 까지
**실제 경로를 그대로** 지나간다. (기존 '기기' 버튼은 표시만 확인한다)

## 4. 서비스워커도 함께 올라갔다 (v. 26-0828-7)

⚠️ 서비스워커는 **개발본이 따로 없다.** 개발본은 Firebase 가 꺼져 있어 푸시를 받을 수
없고, 같은 스코프(`/`)에 워커를 두 개 등록할 수도 없다 — 등록은 스크립트 주소가 아니라
**스코프**로 하나만 잡혀서, 개발용을 등록하면 **운영 워커가 대체된다.**

그래서 워커는 `tests/test_notif_sw.js`(37건)로 먼저 검증한 뒤 운영에 올렸다.
기기에서는 앱을 껐다 켜면 새 워커로 바뀐다 (`skipWaiting` + `clients.claim`).

진단 화면 머리줄에 **앱 버전과 워커 버전이 따로** 나온다. 둘 다
`v. 26-0828-7` 로 보이면 새것이 적용된 것이다.

## 5. 아이폰에서 확인하는 순서

1. 아이폰 홈 화면의 **BLOCK7** 앱을 완전히 껐다가(앱 스위처에서 위로 밀어 없애고) 다시 연다.
   — 새 서비스워커로 바뀌려면 한 번은 그래야 한다.
2. 말씀 설정 → 알림 탭 → **알림 진단 기록 → 보기** → 맨 아랫줄이
   `앱 v. 26-0828-7 · 워커 v. 26-0828-7 · controller 있음` 이면 새것이 적용된 것이다.
   워커가 옛 버전으로 보이면 앱을 한 번 더 껐다 켠다.
3. 말씀 설정 → 알림 탭 → **말씀 클릭 경로 테스트 → 시작**
   - 홈 버튼으로 나가서 **알림센터의 그 알림을 직접 누른다**
   - 그 말씀 전체화면이 뜨면 성공
4. 실패하면 **바로** 말씀 설정 → 알림 탭 → **알림 진단 기록 → 복사** 를 눌러
   클로드에게 붙여넣어 준다.
5. 반복 조건도 함께 봐 준다:
   - 앱을 **완전히 종료**하고(앱 스위처에서 위로 밀어 없애고) 눌렀을 때
   - 앱이 **뒤에 오래 있다가** 눌렀을 때 (10분 이상)
   - 이미 **다른 말씀 전체화면**을 보는 중에 눌렀을 때
   - **같은 말씀** 알림을 연달아 두 번 눌렀을 때

## 8. 건드리지 않은 것 (그대로 지켜진다)

- `notificationclick` 은 여전히 `importScripts` **앞에** 등록된다
- 클릭 처리에서 IndexedDB 저장을 **기다리지 않는다** (시간 제한 걸고 따로 돌린다)
- `client.navigate()` 는 **쓰지 않는다**
- 목표 말씀은 `_vfOverrideVerse` 로 고정한다 (동기화가 못 건드린다)
- **실제로 그 말씀이 표시된 것을 확인한 뒤에만** pending 을 지운다
- 같은 장절이라도 **새 알림이면 다시 연다**
- 주소 · SW 메시지 · BroadcastChannel · IndexedDB pending 의 **네 갈래**를 모두 유지
- 알림 전체화면을 닫으면 **이전 화면을 복원**한다
- 1.5초 폴링에 `visibilityState==='visible'` 조건을 **다시 걸지 않았다**
- 알림 수신·표시 코드는 **한 줄도 바꾸지 않았다**
