# 심방 노트 — 처음 설정과 연결 시험(C0) (HB, 한 번만)

심방 노트(`sweeter.my/care/`)는 심방 내용을 **HB 님의 구글 시트에만** 둡니다. 앱은 그 시트를 읽고 쓰는 창이고,
구글 열쇠는 BLOCK7 구글 캘린더 연결과 **같은 서버 · 같은 열쇠**를 씁니다(`gcal-functions/`). 그래서 할 일은
① 구글 클라우드에서 문 몇 개 열기 ② 서버 다시 올리기 ③ 시험용 사본 · '심방' 캘린더 만들기 ④ 앱에서 시험 — 넷입니다.

> ⚠️ 1·2장을 하기 전에는 앱의 "구글 연결"이 BLOCK7 으로 돌아가 버립니다(서버가 아직 sweeter.my/care 를 모름).

## 1. 구글 클라우드 — API 세 개 켜기

1. https://console.cloud.google.com → 위쪽 프로젝트가 **block7-8f24e** 인지 확인
2. 위 검색창에 **Google Sheets API** → 결과를 눌러 **사용** (파란 단추)
3. 같은 방법으로 **Google Forms API** → **사용**
4. 같은 방법으로 **Google Picker API** → **사용**
   - 이미 '사용 중' 이면 그대로 두면 됩니다.

## 2. 구글 클라우드 — 권한 하나 · 키 하나

**권한 (고른 파일만)** — 왼쪽 메뉴 ☰ → **API 및 서비스** → **OAuth 동의 화면**(새 화면에서는 **Google 인증 플랫폼**)

1. 왼쪽 **데이터 액세스** → **범위 추가 또는 삭제**
2. 아래 '직접 범위 추가' 칸에 이 한 줄을 붙여 넣고 **표에 추가** → **업데이트** → 맨 아래 **저장**
   - `https://www.googleapis.com/auth/drive.file`
   - 이것은 "HB 님이 고르기 창에서 **고른 파일만**" 여는 권한입니다(가안, 2026-11-06 결정). 민감하지 않은 범위라 심사가 필요 없습니다.

**키 (고르기 창 전용)** — ☰ → **API 및 서비스** → **사용자 인증 정보** ✅ 2026-11-06 HB 만듦 · 앱에 넣음 (care v. 26-1106-2)

⚠️ **'Browser key (auto created by Firebase)' 는 고치지 마세요.** 로그인 · 동기화가 함께 쓰는 키라,
제한 목록을 고쳐 저장하면 구글이 "현재 사용 중이므로 중단될 수 있음" 경고를 띄웁니다(2026-11-06 HB 가 만남 → 취소).
대신 고르기 창만 쓰는 키를 **따로** 만듭니다:

1. 위쪽 **+ 사용자 인증 정보 만들기** → **API 키**
2. 만들어진 키의 편집 화면에서 이름 `심방 노트 고르기 창`
3. **애플리케이션 제한사항** → **웹사이트** → **+ 추가** → `https://sweeter.my/*` → **완료**
4. **API 제한사항** → **키 제한** → **Google Picker API** 하나만 → **확인** → **저장**
5. 키(`AIza…`)를 클로드에게 알려 주면 앱(`care/index.html` 의 `PICKER_KEY`)에 넣는다. 공개되어도 되는 키다(3·4번 제한 때문).

## 3. 서버 다시 올리기 (구글 Cloud Shell)

1. https://console.cloud.google.com → 프로젝트 **block7-8f24e** → 오른쪽 위 **>_ (Cloud Shell 활성화)**
2. 한 줄을 붙여 넣고 엔터:

```
cd ~/block7 && git pull && cd gcal-functions && firebase deploy --only functions:gcal
```

- 성공 표시: `gcal(asia-northeast3)` 가 **Successful update operation**
- ⚠️ 배포 중에 **삭제(deletion)를 묻는 화면이 나오면 반드시 N**
- `~/block7` 이 없다고 나오면: `git clone https://github.com/Underkut/block7.git ~/block7 && cd ~/block7/gcal-functions/src && npm install && cd ..` 다음에 위 `firebase deploy …` 한 줄
- 비밀번호(클라이언트 ID · 보안 비밀번호)는 캘린더 때 넣은 것을 그대로 씁니다. 다시 넣지 않습니다.

## 4. 시험용 사본 만들기 (진짜 시트는 건드리지 않게)

C0 쓰기 시험은 **사본**에서만 합니다. 앱도 기록이 10줄 넘는 시트에는 쓰지 않습니다.

1. 지금 쓰시는 **심방 케어** 구글폼을 엽니다(편집 화면)
2. 오른쪽 위 **⋮** → **사본 만들기** → 이름 `심방 케어 (시험)` → **사본 만들기** → 사본이 열립니다
3. 사본 화면 위쪽 **응답** 탭 → **Sheets에 연결**(초록 표 모양) → **새 스프레드시트 만들기** → **만들기**
   - 새 시트 `심방 케어 (시험) (응답)` 이 생깁니다. 비어 있어도 됩니다.
4. (해 보면 좋은 것) 사본 폼에 질문을 하나 더합니다: **+** → 질문 제목 `장소 · 메모` (가운뎃점 그대로) → 종류 **단답형**.
   방식과 장소를 따로 적기로 한 것(3번 답)을 미리 시험해 봅니다.

## 5. '심방' 캘린더 만들기

1. PC 에서 https://calendar.google.com
2. 왼쪽 **다른 캘린더** 옆 **+** → **새 캘린더 만들기**
3. 이름에 정확히 `심방` → **캘린더 만들기**
   - 앱은 이름이 `심방` 인 캘린더를 찾습니다. 색은 마음대로 고르셔도 됩니다.

## 6. 앱에서 연결 시험

1. **https://sweeter.my/care/** 를 엽니다 (PC 크롬 추천 — 고르기 창이 넓습니다)
2. **로그인** — BLOCK7 · Sweeter 와 같은 이메일 · 비밀번호
3. **구글 연결** → 구글 화면
   - "Google 에서 확인하지 않은 앱" 이 나오면 **고급** → **block7-8f24e(으)로 이동** (캘린더 때와 같습니다)
   - 권한 목록의 **체크 칸을 모두 켜고** → **계속**
   - 이미 캘린더를 연결해 둔 계정이면 '연결됨' 으로 뜹니다. 그래도 **"다시 연결"을 한 번** 눌러 새 권한(고른 파일만)을 받아 주세요.
4. **시트 고르기** → `심방 케어 (시험) (응답)` / **폼 고르기** → `심방 케어 (시험)`
5. 아래 **연결 시험** 1 → 6 을 차례로 누릅니다
   - 5번을 누른 뒤 나타나는 **폼 열기 ↗** 로 폼을 하나 제출합니다(이름 · 내용은 아무렇게나, 예: `시험`)
   - 그다음 **6번** — "C0 통과" 가 뜨면 끝입니다
6. 화면을 **캡처해서** 보내 주세요. 빨간 **!** 가 뜬 단계가 있으면 그 글도 함께요.

### (덤) 진짜 시트 읽기 시험

C0 를 통과한 뒤 **시트 고르기**에서 진짜 `HB 심방 케어 (Responses)` 를 고르고 **1번 · 2번만** 눌러 보세요.
읽기만 합니다(4~6번은 앱이 스스로 거절합니다). 날짜를 몇 줄 읽었는지, 기타 글이 몇 가지인지가 나옵니다.
끝나면 다시 사본을 골라 두셔도 되고, 그대로 두셔도 됩니다.
