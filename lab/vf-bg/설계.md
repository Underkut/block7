# 말씀 전체화면 '내 배경' — 설계

> 사용자가 자기 사진(밤하늘 같은 것)을 올려 전체화면 배경으로 쓰고,
> 템플릿(틀)을 얹어 프리셋으로 저장하는 시스템.
> 코드는 이 폴더에 있고 **아직 앱에 넣지 않았다** (합치는 법은 INTEGRATION.md).

---

## 1. HB 가 보는 그림 — 이렇게 쓰인다

1. 말씀 설정 → 전체화면 → **내 배경** 에서 `+ 사진` 을 누른다
2. 아이폰 사진첩에서 밤하늘 사진 하나를 고른다
3. **배경 만들기** 화면이 뜬다. 위쪽은 진짜 말씀이 얹힌 미리보기, 아래쪽은 조절판
   - **틀 여섯 개** — 별밤 · 창가 · 유리 · 필름 · 먹지 · 포스터
     하나만 누르면 어둡기·흐림·글씨체·결이 한꺼번에 그 분위기로 맞춰진다
   - 사진을 **끌어서** 자리를 옮기고, **두 손가락으로** 크기를 맞춘다
   - 더 만지고 싶으면 어둡게 · 흐리게 · 선명도 · 색온도 · 종이결 · 가장자리 ·
     그림자를 하나씩 민다
   - 조절판 위에 **`읽기 좋아요 · 16.7:1`** 처럼 지금 글씨가 얼마나 잘 읽히는지 늘 떠 있다
4. **저장** → 그 배경이 켜지고, 전체화면이 바로 그 사진이 된다
5. 만든 배경은 기본 테마 여덟 개와 **같은 줄에 선다**. 켜고 끄고, 여러 개 켜서
   시간구간마다 다르게 배정하는 것도 그대로 된다 (새벽엔 밤하늘, 낮엔 창가처럼)
6. 칩을 **길게 누르면** 고치기 · 이름 바꾸기 · 지우기

말씀을 넘기면 배경은 그대로 있고 말씀만 바뀐다. 공유 이미지(종이비행기)로 저장해도
**화면에서 본 그대로** 사진 배경이 들어간다.

### 기기 두 대를 쓸 때
사진은 **그 기기에만** 담긴다. 그래서 아이폰에서 만든 배경을 맥에서 열면
"사진에서 뽑은 색"으로 보인다 (같은 색감·같은 글씨·같은 결, 사진만 없다).
맥에서 같은 사진을 한 번 고르면 똑같아진다.
까닭은 3장에 적었다 — 사진을 클라우드에 올리는 것은 **동기화 사고의 씨앗**이라 안 한다.

## 2. 구조 — 이음매는 CSS 변수 하나

지금 앱은 전체화면 배경을 이렇게 칠한다.

```
_vfTheme()  →  _vfBgCss()  →  --vf-bgimg  →  #verseFull · #verseGrid · 앱 바탕
                                          →  _shotDraw() (공유 이미지 캔버스)
```

**여기 딱 얹었다.** `--vf-bgimg` 는 CSS `background` 값이라 여러 겹을 넣을 수 있다.

```
--vf-bgimg: [스크림 그라디언트], url('사진') 50% 45%/cover no-repeat, [팔레트 색]
             ↑ 어둡게 덮는 겹      ↑ 구운 사진        ↑ 사진이 아직 없을 때 바탕
```

그래서 **`#verseFull` 안에 새 요소를 하나도 안 넣었다.** 지금 다른 창에서
전체화면 화면 구조를 고치고 있어도 부딪히지 않는다.

| 층 | 무엇으로 | 왜 |
|---|---|---|
| 사진 | 구운 이미지 한 장 | 화면에서 filter 를 안 돌린다 (넘길 때 안 버벅인다) |
| 스크림(어둡게) | CSS 그라디언트 | 값을 바꿔도 사진을 다시 굽지 않는다 |
| 종이결 · 비네트 | 이미 있는 `--vf-grain` · `--vf-vig` | 기본 테마와 같은 그림을 쓴다 |
| 글씨 그림자 | 새 변수 `--vf-tsh` | 기본 테마에서는 비어 있어 지금 화면이 안 바뀐다 |

### 굽는다 = 자르기 · 축소 · 흐림 · 채도 · 색온도를 미리 끝내 둔다
전체화면은 **손가락으로 넘기는 화면**이다. 배경에 `filter: blur()` 가 걸려 있으면
넘길 때마다 다시 계산돼 버벅인다. 그래서 고를 때 한 번 구워 두고, 화면에서는
평범한 `background-image` 로 깐다. 공유 이미지(캔버스)도 **같은 한 장**을 그대로
그리므로 화면과 어긋날 수가 없다.

### 미리보기 · 화면 · 공유 이미지가 같은 그림인 까닭
셋 다 `_vfbgCover()` **한 함수**로 자리를 잡는다 (CSS `background-size:cover` +
`background-position:%` 와 같은 계산). 흐림 세기도 `_vfbgBlurPx()` 하나를 나눠 쓴다 —
상자의 짧은 변에 비례하므로 작은 미리보기와 큰 사진이 같은 정도로 흐려진다.
편집기 미리보기는 "cover 로 깔고 focus 를 축으로 zoom 배 확대", 저장은
"zoom·focus 로 자른 뒤 cover" 인데 **둘은 수학적으로 같은 결과**다
(tests 시나리오 2 가 지킨다).

## 3. 사진은 어디에 두는가 — 그리고 왜 클라우드가 아닌가

| 무엇 | 어디 | 크기 |
|---|---|---|
| 구운 사진 (화면에 깔리는 것) | IndexedDB `b7bg:<id>` | 100~400KB |
| 재편집용 원본 | IndexedDB `b7bg:<id>:src` | 150~500KB |
| 프리셋 정보 (이름·틀·편집값·팔레트·1KB 미리보기) | `ST.settings.vfBgs` → 클라우드 | 12개 다 채워도 30KB 아래 |

**사진을 클라우드에 안 올리는 까닭 세 가지**

1. 클라우드 문서 하나는 1MB 다. 사진 두 장이면 앱 상태 전체가 못 올라간다 —
   그 순간 **할일·말씀 기록까지 같이 못 올라간다.**
2. 이 저장소의 사고는 전부 "동기화가 무엇을 지웠나" 였다 (2026-08-02, 2026-08-31).
   사진처럼 큰 것을 3자 병합에 태우면 새로운 사고 면이 생긴다.
3. 사진이 없어도 **일이 되게** 만들 수 있다 — 사진에서 뽑은 색 두 개와 1KB 미리보기가
   설정에 함께 실려 가므로, 다른 기기에서도 같은 분위기가 그대로 난다.

**사진을 지우는 길은 하나뿐이다.** 사용자가 칩을 길게 눌러 '지우기' 를 누르고 확인한
그 한 번. 원격에서 목록이 비어 와도 보관소는 건드리지 않는다.
(2026-08-02 규칙 — "외부에서 받아온 데이터로 지우는 동작에는 반드시 상한을 둘 것")
`tests/test_vfbg.js` 시나리오 9 가 코드에 그 길이 하나뿐인지 검사한다.

## 4. 가독성 — 이 기능이 실패하는 유일한 방법

사진 배경의 진짜 위험은 예쁘지 않은 것이 아니라 **말씀이 안 읽히는 것**이다.

- 사진에서 색을 뽑을 때 평균을 **본문이 앉는 가운데 띠**에서 잰다.
  화면 전체로 재면 "하늘은 밝고 땅은 캄캄한" 사진에서 평균이 중간으로 나와
  어느 쪽 글씨도 안 읽힌다.
- 그 평균색에 대해 흰 글씨·검은 글씨 중 잘 읽히는 쪽을 고르고,
  **명암비 4.5:1** 을 넘길 때까지 스크림 알파를 0.02 씩 올린다 (WCAG 본문 기준).
- 틀(템플릿)이 정한 어둡기와 **큰 값**을 쓴다. 별밤 사진이 이미 어둡다고 스크림을
  0 으로 두면 템플릿이 뜻한 깊이가 사라지고, 반대로 밝은 사진에서 템플릿 값만
  쓰면 글씨가 묻힌다.
- 편집기에 지금 명암비가 늘 떠 있다. 3:1 아래면 빨간 글씨로 "글씨가 묻혀요".
- 여섯 종류 사진(밤하늘·눈밭·노을·숲·모래·회색벽)으로 테스트가 이것을 지킨다.

## 5. 일부러 하지 않은 것

| 안 한 것 | 까닭 |
|---|---|
| 사진 클라우드 동기화 | 3장. 대신 기기마다 한 번 고르면 된다 |
| 배경마다 다른 글씨 크기 | 크기는 이미 핀치·설정으로 사용자가 정한다. 두 곳에서 정하면 싸운다 |
| 사진 여러 장 슬라이드쇼 | 넘김 애니메이션과 부딪힌다. 배경을 여러 개 만들어 시간구간에 배정하면 같은 일이 된다 |
| 글씨색 자유 선택(색상환) | 자동으로 고른 두 가지(밝게/어둡게)로 충분하고, 자유 선택은 안 읽히는 조합을 만든다 |
| 말씀 위젯 배경 | 위젯은 작아서 사진이 뭉갠다. 나중에 필요하면 색만 |
